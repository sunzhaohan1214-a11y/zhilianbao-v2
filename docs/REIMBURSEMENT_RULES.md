# 智链宝 V2.0 — REIMBURSEMENT_RULES.md

> 版本：v1.0  
> 状态：已确认业务规则 + 1项待财务制度补充  
> 重要：线上是“核对与材料流转记账”，不是财务审批系统。

## 1. 报销类型

只保留：

```text
差旅报销
活动报销
```

## 2. 差旅固定四类

### 2.1 交通费

指符合差旅规则的实际交通费用。

当前明确包含示例：

```text
飞机票
高铁票
```

当前明确不包含：

```text
出租车
网约车
```

出租车/网约车票据被OCR识别后：

> 提示“不属于当前差旅交通费范围”，不得自动归交通费。

### 2.2 交通补助

参考：

```text
80 元/天
```

原则人工填写。

不要求上传交通票据证明补助。

不由 OCR 产生。

### 2.3 伙食补助

参考：

```text
100 元/天
```

原则人工填写。

实际餐饮发票不作为“伙食补助票据”。

不由 OCR 产生。

### 2.4 住宿费

实际住宿费用。

酒店等合规住宿票据可由OCR建议归入住宿费。

## 3. 差旅实际餐饮

```text
不进入差旅报销。
```

若属于活动实际支出：

> 在活动报销中按费用明细填写。

## 4. 活动报销

活动报销不是“餐饮报销”。

采用灵活多明细：

```text
餐饮
场地
材料制作
物料
住宿
交通相关
其他
```

以上只是常用类型。

业务不能被默认类型锁死。

选择：

```text
其他
```

必须填写：

```text
费用名称
```

## 5. OCR规则

OCR事实：

```text
票据类型
日期
金额
销售方
发票号码
```

分类只是建议。

### 差旅

- 飞机/高铁 → 可建议交通费；
- 酒店 → 可建议住宿费；
- 出租车/网约车 → 警告，不自动归交通费；
- 餐饮 → 警告，不自动归差旅；
- 补助 → OCR不生成。

### 活动

OCR建议类型后：

> 申请人可人工更改。

## 6. 无票据费用

允许按实际规则手工填写：

```text
项目
金额
说明
```

不增加额外AI判断流程。

## 7. 重复票据

系统可做：

```text
精确发票号码重复
```

基础检查。

不要：

- 宣称验真；
- 模糊相似就阻止；
- 正常情况下不停重复提醒。

明确重复时：

> 阻止或提示人工核对。

## 8. 金额

所有金额 Decimal。

`total_amount`：

> 服务端根据正式费用明细重新计算。

前端不得决定最终合计。

## 9. 关联行程

只能选择：

> 已完成行程。

提交时保存快照：

- 日期；
- 地点；
- 参与人；
- 工作内容。

后续行程修改：

> 不改变已提交报销。

同一行程多人：

> 每人各自报销。

## 10. 状态

```text
草稿
→ 待线上核对
→ 退回修改 / 已核对（待交纸质材料）
→ 已收材料
→ 已提交财务
```

“已提交财务”：

> 只表示纸质材料已交财务。

绝不解释为：

- 财务审批通过；
- 已付款。

V2第一阶段不增加“已付款”。

## 11. 退回和撤回

- 待线上核对前，申请人可撤回回草稿；
- 退回必须原因；
- 修改后重新提交；
- 历次版本保留；
- 待交纸质材料发现线上内容错，可退回修改；
- 已收材料发现不完整，可回待交纸质材料。

## 12. 状态纠正

报销管理可纠正误操作：

```text
from_state
to_state
reason
operator
time
```

完整审计。

纠正“已提交财务”：

> 只纠正平台记录，不声称改变线下事实。

## 13. 纸质材料提醒

**不设置系统催交提醒。**

## 14. A4/Excel输出

必须把差旅四类分列保留：

```text
交通费
交通补助
伙食补助
住宿费
```

不能合成一个“差旅费”。

活动报销输出多条费用明细。

## 15. 唯一尚未确定的计算规则

PRD 尚未定义：

> 交通补助 / 伙食补助的具体计发天数。

包括：

- 当天往返；
- 跨日；
- 部分日；
- 特殊情形。

第一阶段：

```text
reference_rate
claimed_days
claimed_amount
calculation_note
```

人工按实际财务制度填。

Codex不得自行实现：

```text
days = endDate - startDate + 1
```

等猜测公式。

财务制度明确后，形成：

```text
REIMBURSEMENT_RULES v1.1+
```

再开发自动计算。
