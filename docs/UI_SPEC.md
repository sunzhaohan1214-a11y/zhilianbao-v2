# 智链宝 V2.0 — UI_SPEC.md

> 版本：DESIGN v1.1
> 状态：视觉与交互基线  
> 说明：锁定信息架构、页面结构、组件语言和交互原则。Logo、荷宝最终矢量资产可替换，但不得因此改变页面结构。

## 1. 视觉方向

关键词：

```text
iOS / Apple-like
简约
轻
留白
克制
内容优先
内部工作工具
```

明确不要：

- 深蓝“政务大屏”；
- 九宫格功能入口；
- 巨型数据看板；
- 霓虹AI渐变；
- 大面积高饱和色；
- 3D科技舞台；
- 重阴影卡片墙；
- 每个功能不同颜色；
- 全局悬浮“+”。

## 2. 基础设计系统

### 2.1 颜色

建议使用 token，不在页面直接写十六进制：

```text
--bg-primary
--bg-grouped
--surface
--surface-secondary
--text-primary
--text-secondary
--text-tertiary
--separator
--brand
--brand-soft
--success
--warning
--danger
--info
```

原则：

- 主背景浅灰白；
- 卡片白色/浅色；
- 品牌蓝只用于主操作和关键强调；
- 状态色仅用于状态；
- 不让每张卡片都有彩色背景。

### 2.2 字体

系统字体优先：

```text
-apple-system
BlinkMacSystemFont
"SF Pro"
"PingFang SC"
"Microsoft YaHei"
sans-serif
```

中文不额外打包私有字体。

建议层级：

```text
页面大标题    24–28 / Semibold
模块标题      17–20 / Semibold
正文          15–17 / Regular
辅助文字      13–14
微型标签      11–12
```

### 2.3 圆角与空间

统一 token：

```text
radius-s  8
radius-m  12
radius-l  16
radius-xl 20
```

手机主卡片优先 16–20。

间距使用 4 / 8 / 12 / 16 / 20 / 24 / 32 体系。

### 2.4 阴影

少用。

优先：

```text
分组背景
+ 1px separator
+ 极轻 shadow
```

而不是浮夸投影。

```text

```

# 6. Mobile 首页

固定顺序：

```text
顶部栏
荷宝 AI
公告
团队协调角色全团概览（仅 GROUP_LEADER / MINISTER）
当前在宝
今日行程
我的待办
最新需求
底部导航
```

顶部：

```text
智链宝 Logo/名称
消息
头像
```

不放：

- 日期；
- 天气；
- 欢迎词；
- 大标语。

### 公告

最多1条：

```text
本人待确认的重要公告
→ 管理员置顶
→ 最新公告
```

没有则隐藏。

### 团队协调角色全团概览

仅 `GROUP_LEADER` 或 `MINISTER`：

```text
待对接
对接中
久未更新
待办结审核
```

紧凑，不做大仪表盘。

两个角色共用同一概览组件和能力判断，不复制页面逻辑。需要展示角色身份时：

```text
GROUP_LEADER → 团长
MINISTER → 部长
```

不得把部长显示成团长；同一人员多角色仍不要求切换身份。

### 当前在宝

展示：

```text
总人数
最多5个头像/姓名
+N
在任 X · 往届 Y
```

允许有资格用户进入来离宝报备。

### 今日行程

最多3条。

共享行程只出现一次。

### 我的待办

最多3条。

只展示当前立即可执行事项。

优先级由首页只读派生：业务紧急度优先，其后按业务截止时间；读取首页不得改写 Todo 状态。业务终态与 Todo 不一致时必须 fail-safe 隐藏。

### 最新需求

最多3条。

AI 推荐给当前用户的需求可优先。

首页不直接认领，必须进入详情。

### 荷宝降级入口

在独立对话路由上线前，荷宝保留小头像与明确的能力缺口说明，并链接至已上线的政策、企业、团员结构化检索；不得伪造聊天能力或假数据。

### M1-006 lifecycle detail

当前移动端与管理端详情共用单页生命周期面板，已实现：

```text
最新在前的 Progress 时间线
当前进展 / 下一步提交
上海自然日 stale 标签与团队协调提醒
办结提交、历史 CloseRequest / Review
ADMIN / SUPER 核验后退回或通过
current owner 申请退出、ADMIN / SUPER 审核
SUPER owner transfer preview / second confirm
合法状态下取消
completedAt / completionBatchId 或 canceled reason 展示
```

Progress 每条显示时间、真实提交人、来源、当前进展、下一步和附件。历史往届代理录入明确显示代理 actor 与 represented person，不冒充往届本人在线提交。

动作按责任和状态动态出现：

- current owner：新增进展、提交办结、申请退出；
- active collaborator：仅补充进展；
- ALUMNI_PLATFORM active helper：仅补充进展；
- current township handler：新增进展、代理历史往届、提交办结；
- 负责镇区其他 staff：补充进展，不能替 handler 提交办结；
- GROUP_LEADER / MINISTER：仅 stale 时显示低强调提醒；
- ADMIN / SUPER：办结审核、退出审核；
- SUPER：管理区显示高风险转交，必须先生成影响预览，再二次确认。

`PENDING_CLOSE_REVIEW` 显示“待办结审核”，CloseRequest 不可编辑且不开放普通 Progress。`COMPLETED` 显示已办结、办结时间/批次、最终核验和全部历史；`CANCELED` 显示取消事实。两种终态均不显示继续进展或再次提交办结。

SUPER 转交预览展示 old/new owner、active collaborator 数、是否跨批次与责任影响；确认后立即生效，新 owner 无线上接受步骤。

### M1-007 Outcome detail

办结审核仍在原单页完成。APPROVE 前必须选择“不跟踪/需要跟踪”，TRACKING 同表单填写首次上海自然日；RETURN 不携带策略。COMPLETED 详情在生命周期区后显示“成效跟踪”，不新增全局导航、Home 卡片、Dashboard 或额外跳转。

顶部显示 Plan 中文状态、首次/下次日期和服务端 `approvedTotals`；金额两位小数、千分位、人民币符号。普通内部只显示 APPROVED 卡片与合计。负责镇区在到期且无活动轮次时显示“填报本轮成效”，字段明确标注“本轮新增”，显式保存草稿，支持 RETURNED 修改与重提。ADMIN/SUPER 在 PENDING_REVIEW 卡片显示退回原因/线下核实表单；无佐证时提示 `verifiedNote` 必填。

Round 卡片显示轮号、实际跟踪日期与批次、六类增量、定性结果、企业反馈、下一日期或结束选择、状态、佐证、退回原因及核实说明。NOT_TRACKED 无填报入口；ENDED 显示“已结束”且无重开动作。所有按钮仍受服务端权限和状态校验，隐藏按钮不是授权边界。

# 24. 全局页面状态

每个页面必须实现：

```text
loading
empty
error
offline/retry
forbidden
not-found
merged
canceled/withdrawn
```

禁止空白页。

### Loading

使用骨架屏 / 局部 Loading，不让整页闪烁。

### Empty

说明：

- 为什么为空；
- 有权限时给一个主操作。

### Error

显示：

```text
发生了什么
重试
返回
```

不展示技术堆栈。

### Forbidden

明确：

> 当前账号无权查看该内容。

不要伪装成系统故障。

2. 不增加全局“+”；
3. 不用九宫格；
4. 不做政务蓝大屏；
5. 不做彩色指标卡墙；
6. 不让荷宝占据大面积首页；
7. 不使用全身公仔大图作为长期首页主体；
8. 一个页面只突出一个主要动作；
9. 详情尽量单页；
10. 状态名用业务中文；
11. 不展示技术枚举；
12. 不因为管理员能力多就在手机塞大量治理入口；

14. Logo与Mascot资产替换不能破坏布局；
15. 所有重要页面必须有 Loading/Empty/Error/Forbidden。

## M3-005 PC Admin 导入

流程固定为：批次列表 → 上传 `.xlsx` → 选择 Sheet → Mapping → Preview/Resolve → 二次确认 → Result。手机端不增加入口。

列表只展示文件、类型、状态、创建人、时间、行数和待处理数；Preview 默认脱敏手机号。人工消歧同时展示本次 Excel 关键值与候选的姓名/企业名/人才名及最小业务摘要，不以 UUID 作为主要标签；ARCHIVED 人员、DISABLED/MERGED 企业只能跳过并提示先走治理流程。

首层“确认导入”只打开 Dialog；Dialog 必须展示创建/更新/关联/跳过数、总行数、Preview Version、整批回滚说明，并在管理员勾选已核对后才允许“确认执行导入”发起 POST。取消 Dialog 不产生业务写入；服务端 stale preview 仍返回 `IMPORT_PREVIEW_STALE`，前端关闭 Dialog 并刷新。
