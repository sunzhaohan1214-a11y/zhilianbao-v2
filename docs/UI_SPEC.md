# 智链宝 V2.0 — UI_SPEC.md

> 版本：DESIGN v1.1
> 状态：视觉与交互基线  
> 说明：锁定信息架构、页面结构、组件语言和交互原则。Logo、荷宝最终矢量资产可替换，但不得因此改变页面结构。

## 1. 视觉方向

关键词：

```text
iOS / Apple-like
简约
轻
留白
克制
内容优先
内部工作工具
```

明确不要：

- 深蓝“政务大屏”；
- 九宫格功能入口；
- 巨型数据看板；
- 霓虹AI渐变；
- 大面积高饱和色；
- 3D科技舞台；
- 重阴影卡片墙；
- 每个功能不同颜色；
- 全局悬浮“+”。

## 2. 基础设计系统

### 2.1 颜色

建议使用 token，不在页面直接写十六进制：

```text
--bg-primary
--bg-grouped
--surface
--surface-secondary
--text-primary
--text-secondary
--text-tertiary
--separator
--brand
--brand-soft
--success
--warning
--danger
--info
```

原则：

- 主背景浅灰白；
- 卡片白色/浅色；
- 品牌蓝只用于主操作和关键强调；
- 状态色仅用于状态；
- 不让每张卡片都有彩色背景。

### 2.2 字体

系统字体优先：

```text
-apple-system
BlinkMacSystemFont
"SF Pro"
"PingFang SC"
"Microsoft YaHei"
sans-serif
```

中文不额外打包私有字体。

建议层级：

```text
页面大标题    24–28 / Semibold
模块标题      17–20 / Semibold
正文          15–17 / Regular
辅助文字      13–14
微型标签      11–12
```

### 2.3 圆角与空间

统一 token：

```text
radius-s  8
radius-m  12
radius-l  16
radius-xl 20
```

手机主卡片优先 16–20。

间距使用 4 / 8 / 12 / 16 / 20 / 24 / 32 体系。

### 2.4 阴影

少用。

优先：

```text
分组背景
+ 1px separator
+ 极轻 shadow
```

而不是浮夸投影。

# 3. 荷宝 AI

首页荷宝不是大型 Banner。

推荐结构：

```text
荷宝小头像/胸像
+
“问政策、查企业、找团员”
+
轻量输入入口
```

公仔使用：

- 小头像；
- 胸像；
- 半身轻微探出；

不长期使用大面积全身照占据首页。

荷宝图像资产必须独立组件：

```text
MascotAvatar
```

后期换最终公仔不改布局。

# 4. Logo

顶部展示最终智链宝 Logo + “智链宝”。

Logo 是可替换品牌 Asset：

```text
BrandLogo
```

不得在多个页面手工复制图片路径。

# 5. Mobile 全局导航

底部固定且只允许四项：

```text
首页
需求
资源
我的
```

禁止第五项。

禁止全局悬浮加号。

一级页面显示底部导航。

详情/创建/审核等二级页：

- 隐藏底部导航；
- 顶部返回；
- 返回后恢复列表搜索、筛选、滚动位置。

---

# 6. Mobile 首页

固定顺序：

```text
顶部栏
荷宝 AI
公告
团队协调角色全团概览（仅 GROUP_LEADER / MINISTER）
当前在宝
今日行程
我的待办
最新需求
底部导航
```

顶部：

```text
智链宝 Logo/名称
消息
头像
```

不放：

- 日期；
- 天气；
- 欢迎词；
- 大标语。

### 公告

最多1条：

```text
本人待确认的重要公告
→ 管理员置顶
→ 最新公告
```

没有则隐藏。

### 团队协调角色全团概览

仅 `GROUP_LEADER` 或 `MINISTER`：

```text
待对接
对接中
久未更新
待办结审核
```

紧凑，不做大仪表盘。

两个角色共用同一概览组件和能力判断，不复制页面逻辑。需要展示角色身份时：

```text
GROUP_LEADER → 团长
MINISTER → 部长
```

不得把部长显示成团长；同一人员多角色仍不要求切换身份。

### 当前在宝

展示：

```text
总人数
最多5个头像/姓名
+N
在任 X · 往届 Y
```

允许有资格用户进入来离宝报备。

### 今日行程

最多3条。

共享行程只出现一次。

### 我的待办

最多3条。

只展示当前立即可执行事项。

### 最新需求

最多3条。

AI 推荐给当前用户的需求可优先。

首页不直接认领，必须进入详情。

# 7. 需求中心

顶层只有：

```text
全部需求
我的需求
```

搜索 + 折叠筛选：

```text
状态
类型
镇区
```

`我的需求` 表示：

- 主责；
- 协同；
- 往届协助；
- 组织业务关系。

不是“AI推荐列表”。

### 卡片

只突出：

```text
需求标题
企业
镇区
主状态
最多一个关注标签
```

业务编号小号显示。

### 详情

单页，不滥用 Tabs。

顺序：

```text
主状态
标题/企业
企业原始需求
联系人
参与人员
AI推荐（有权时）
进展时间线
来源/附件
历史/审计摘要
```

底部：

```text
一个主按钮
+
更多
```

按角色动态变化。

# 10. 团员

# 17. 报销

### 差旅

视觉固定分成四块：

```text
交通费
交通补助
伙食补助
住宿费
```

交通补助 / 伙食补助必须看起来像：

> 手工补助

而不是“上传票据”。

### 活动

使用：

```text
多条费用明细
```

允许不同类别并存。

OCR：

```text
左/上原票据
右/下识别字段
低置信度明显提示
```

申请人确认后才进入正式明细。

# 24. 全局页面状态

每个页面必须实现：

```text
loading
empty
error
offline/retry
forbidden
not-found
merged
canceled/withdrawn
```

禁止空白页。

### Loading

使用骨架屏 / 局部 Loading，不让整页闪烁。

### Empty

说明：

- 为什么为空；
- 有权限时给一个主操作。

### Error

显示：

```text
发生了什么
重试
返回
```

不展示技术堆栈。

### Forbidden

明确：

> 当前账号无权查看该内容。

不要伪装成系统故障。

# 25. 长表单

必须：

- 自动保存草稿；
- 网络失败不丢内容；
- 附件上传进度独立；
- 返回页面尽量恢复输入；
- 提交前服务端最终校验。

---

# 26. 动画

只使用轻量：

- 页面/卡片淡入；
- Bottom Sheet；
- 状态过渡；
- iOS式反馈。

不做：

- 发光；
- 粒子；
- 大面积3D；
- 复杂开场动效。

---

# 27. 图标

统一线性图标体系。

不要 Emoji 作为功能图标。

不要一个页面混用多套图标库。

---

# 28. UI 红线

1. 底部永远四栏；
2. 不增加全局“+”；
3. 不用九宫格；
4. 不做政务蓝大屏；
5. 不做彩色指标卡墙；
6. 不让荷宝占据大面积首页；
7. 不使用全身公仔大图作为长期首页主体；
8. 一个页面只突出一个主要动作；
9. 详情尽量单页；
10. 状态名用业务中文；
11. 不展示技术枚举；
12. 不因为管理员能力多就在手机塞大量治理入口；
13. 不因UI视觉调整改变已确认权限/流程；
14. Logo与Mascot资产替换不能破坏布局；
15. 所有重要页面必须有 Loading/Empty/Error/Forbidden。

## M3-005 PC Admin 导入

流程固定为：批次列表 → 上传 `.xlsx` → 选择 Sheet → Mapping → Preview/Resolve → 二次确认 → Result。手机端不增加入口。

列表只展示文件、类型、状态、创建人、时间、行数和待处理数；Preview 默认脱敏手机号，阻断行可选择匹配已有、创建新记录或跳过。
